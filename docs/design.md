# Design decisions

## 1. The image proves the modules

The ledger and network modules are not installed from a gallery; the Modules task copies them from the sibling
repos into `build/modules/` and the Dockerfile copies that into the image's PowerShell module path. The end-to-end
run therefore tests exactly the module source on disk, inside the runtime it ships in (Linux, PowerShell 7.4,
non-root), not just on the developer's Windows host. A module change is proven when this repo's build goes green.

## 2. Secrets by mount only

Nothing secret is in the image or in git. `ANTHROPIC_API_KEY` is optional and arrives at run time from a
gitignored `.env` (or the shell) via Compose interpolation. The ledger's HMAC key is generated by the `ledger`
keeper onto the ledger volume, which the agent never mounts. The mitmproxy CA is generated by the sidecar onto its own volume and mounted read-only into the
agent. `.dockerignore` excludes `.env` and `artifacts/` so neither can leak into a build context.

## 3. Ledger on a volume the host keeps, written by a keeper the agent cannot reach

The agent writes unsigned entries to the `spool` volume; the `ledger` container (Claude.Agent.Ledger's keeper,
built from `ledger.Dockerfile`) chains them into the `ledger` volume with a key only it holds. The agent mounts
`spool` and never `ledger`; the keeper runs with `network_mode: none`. See Claude.Agent.Ledger design 3.

`ledger` is a named volume. `docker compose down` keeps it; only `Invoke-Build Clean` removes it. Runs
accumulate entries on one continuous chain, so the history across runs is verifiable, not just the last run.
Smoke waits for the keeper to drain the spool, stops it (SIGTERM, one final flush, must exit 0), then copies
the volume out (`docker cp` from a created-but-never-started container), so verification never depends on any
container being alive or honest at read time. It also asserts that the agent image contains no `key.bin` and
the agent container has no `/ledger` mount.

## 4. A sidecar the agent cannot reach

Traffic is recorded by the `mitm` container from Claude.Agent.Network, and it is the agent's only way out: the
agent is on the internal `inside` network alone, `mitm` bridges `inside` and `outside`, and the proxy env is a
convenience (Claude.Agent.Network design 1). The entrypoint's `agent.egress-check` proves a direct request
fails before every run, and the run aborts if it does not. The agent mounts only the CA (read-only);
the `capture` volume is mounted into `mitm` and into host-started converter containers, never into `agent`.
The agent starts as root only long enough to install the CA into the system store, then re-executes itself as
user `agent` (uid 10001, distinct from mitmproxy's 1000 so it cannot read the CA private key).

## 5. Smoke writes a report, Pester asserts the report

The Smoke task gathers facts (ledger verified, entry kinds of the last run, probe/run outcome, flows to
`api.anthropic.com`, image size) into `artifacts/smoke-report.json`, and fails fast on the essentials. Pester
then asserts the same facts from the report. The report is the durable, diffable record of a run; the Pester
result is the pass/fail record in a format CI already understands. Keeping Docker work out of Pester means the
tests are fast and can be re-run against a saved report.
