# CLAUDE.md

Claude Code container image plus an end-to-end `Invoke-Build` that proves it. One of five repos:

- `Claude.Agent` (this): Dockerfile, `ledger.Dockerfile` (keeper sidecar), `entrypoint.ps1`, `compose.yaml`, `.build.ps1`, `tests/Smoke.Tests.ps1`, `vendor/` (the FileSystem ontology the policy is generated from).
- `Claude.Agent.Ledger`: the ledger module baked into the image.
- `Claude.Agent.Network`: the mitmproxy sidecar (`compose/sidecar.yaml`, pulled in with `include:`) and the host-side capture module.
- `Claude.Agent.Policy`: the tool policy module, schema and Claude Code hooks baked at `/opt/agent/policy`.
- `Claude.Agent.Alerts`: host-only ledger reader; the Alerts task writes its findings as a GraphNode layer.

**Sibling-path assumption:** the other four repos, and `Graph.Node` (GraphNode) and `Graph.Emitter.Agent`, both
read-only here, are checked out next to this one (`../Claude.Agent.Ledger`, `../Claude.Agent.Network`,
`../Claude.Agent.Policy`, `../Claude.Agent.Alerts`, `../Graph.Node`, `../Graph.Emitter.Agent`). `.build.ps1`
(Modules, and Up's export) and `compose.yaml` (`include:`) rely on it.
Each repo is its own git repo; changes that span them are committed in each.

## Commands

- `Invoke-Build`: Modules, Image, Up, Smoke, Alerts, Down, Pester, Runs. Needs Docker running.
- Up replaces a stack that is already up (`-NoReplace` throws instead), then exports the ledger's runs with
  Graph.Emitter.Agent and POSTs `{name: agent-runs, path: <repo>rtifacts\layers}` (the folder, so Portal mounts the newest
  run) to Portal on `http://127.0.0.1:8200` (`-NoPortal` skips; a portal that
  is not up is a warning, not a failure). Design 11.
- `Invoke-Build Clean`: also drops the volumes.
- `Invoke-Build Status`: compose project, its networks and volumes; fails if any host port is published.
- Pester only via `pwsh -NoProfile -File tests/Invoke-Tests.ps1`; it reads `artifacts/smoke-report.json`, so Smoke must have run.

## Rules

- No secrets in the image or git. The API key comes from `.env` (gitignored) at run time; the ledger key and the
  mitmproxy CA are created on volumes. `.dockerignore` keeps `.env` and `artifacts/` out of the build context.
- Never mount the `capture` or `ledger` volume into `agent`; the agent gets `spool` (rw) and `mitm-ca` (ro) only.
- `agent` stays on the `inside` network only, and nothing but `agent` and `mitm` goes on `inside`.
- `build/` is generated by the Modules task; edit the modules in their own repos.
- `build/host-modules/` (Alerts, GraphNode) never goes into an image; keep it in `.dockerignore`.
- `.claude/skills/git-guard`, `run-report` and `graph-node` are copies of Graph's committed (HEAD) skills; recopy,
  never edit (`tests/Skills.Tests.ps1`). git-guard's hook is wired in `.claude/settings.json`. The run-report layer follows that skill's ontology (design 10).
- The agent waits for the keeper to be healthy (its seq sync done); do not weaken `depends_on` to `service_started`.
- No service publishes a host port. `CLAUDE_AGENT_PORT` (8300) is reserved for an Alerts/Ledger API and stays a
  commented `ports:` line until that API exists (design 9). Call Compose only through `Invoke-Compose` in
  `.build.ps1`, so `--project-name` is always passed.
- `/opt/agent/policy` stays root-owned and read-only; the policy is generated in the image build, never edited by hand.
  To change what the agent may do, change Claude.Agent.Policy's defaults or recopy the vendored ontology.
- Bumping Claude Code: change `CLAUDE_CODE_VERSION` in the Dockerfile and the version in the README.
